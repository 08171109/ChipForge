# ChipForge 图像核心技术规格

本文件说明已提供 RTL 使用的像素运算、流式端口与验证要求。机器可读规格位于 `specs/`；整数参考位于 `verification/oracle.py`。三份设计分别为 `sobel_fast`、`sobel_compact` 和 `image_multi`。

图像输入为 8 位无符号灰度，3×3 邻域按规格顺序串行输入。随包图像示例和功能仿真入口见[仿真指南](simulation.md)，工具与工艺环境见[物理实现指南](physical-design.md)。

## 5. 必须冻结的功能规格

### 5.1 Sobel：主功能

输入像素 `pij` 均为 `[0,255]` 的 unsigned 整数。

```text
Gx = (p02-p00) + 2*(p12-p10) + (p22-p20)
Gy = (p00-p20) + 2*(p01-p21) + (p02-p22)
M  = abs(Gx) + abs(Gy)
out = 255 if M > 160 else 0
```

- `Gx/Gy` 范围 `[-1020,1020]`，至少 11-bit signed。
- `M` 的安全上界可取 2040，至少 11-bit unsigned。
- 输入先零扩展再进入 signed 运算；不能把 128–255 的像素当负数。
- 在足够位宽上移位/求和，不能先在 8 位上运算再扩展。
- 阈值固定 160，比较是严格 `>`。第一版不用平方根，不加入语义分割或物体识别。

### 5.2 高斯模糊：扩展功能

```text
S = p00 + 2*p01 + p02
    + 2*p10 + 4*p11 + 2*p12
    + p20 + 2*p21 + p22
out = S >> 4
```

`S` 范围 `[0,4080]`，至少 12-bit unsigned；结果向下取整，无额外四舍五入。

### 5.3 锐化：扩展功能

```text
S = 5*p11 - p01 - p10 - p12 - p21
out = min(255, max(0, S))
```

`S` 范围 `[-1020,1275]`，至少 12-bit signed；最后做 0–255 饱和。

### 5.4 多功能选择

`image_multi`：mode 0=Sobel，1=模糊，2=锐化，3=输出零。mode 在邻域第一个样本被接受时锁存，其后变化不影响该事务。

两份单功能 Sobel 中 mode 端口保留并忽略，改变 mode 不影响输出；其应用能力清单只声明 Sobel。宿主入口必须拒绝向单功能设计请求模糊/锐化。

规格文件示例（待实施者创建，下面是 `sobel_fast` 的冻结起点；完整协议见第 6 节）：

```json
{
  "design_id": "sobel_fast",
  "top_module": "tt_um_cf_sobel_fast",
  "protocol_version": "window9_v1",
  "operations": ["sobel_binary"],
  "pixel_bits": 8,
  "pixel_signed": false,
  "threshold": 160,
  "threshold_comparison": "strict_gt",
  "reserved_mode_behavior": "ignored",
  "latency_after_last_sample": 2,
  "minimum_window_initiation_interval": 11,
  "clock_period_ns": 100,
  "tiles": "2x2",
  "image_size": [128, 128],

```

另两份顶层名固定为 `tt_um_cf_sobel_compact`、`tt_um_cf_image_multi`。`info.yaml`、实际 RTL 顶层、源文件清单及 test/Makefile 配置要一致；不能生成代码后漏掉工具工程接入。

## 6. Tiny Tapeout 接口及周期协议

### 6.1 端口 mapping

| 模板端口 | 含义 |
|---|---|
| `ui_in[7:0]` | 输入灰度像素 |
| `uio_in[0]` | `in_valid` |
| `uio_in[1]` | `start_window`：本样本为新邻域的第一个像素 |
| `uio_in[3:2]` | mode；单功能设计忽略 |
| `uio_out[4]` | `in_ready` |
| `uio_out[5]` | `out_valid` |
| `uio_out[6]` | `busy`：部分邻域已接收或计算尚未完成 |
| `uio_out[7]` | 常量零 |
| `uo_out[7:0]` | 输出像素 |
| `uio_oe[7:0]` | 固定 `8'hf0`：高四位输出，低四位输入 |
| `uio_out[3:0]` | 固定零；对应引脚仍为输入方向 |
| `clk/rst_n/ena` | 单时钟、低有效同步 reset、使能 |

所有未使用端口按官方模板要求处理，不悬空。低四位输入和高四位输出不能接反。

### 6.2 握手与状态

- 在上升沿 `in_valid && in_ready` 才接受一个样本；输入均与该时钟同步，不引入第二时钟域。
- 正常事务：第一个样本 `start_window=1`，随后八个样本为 0；valid 空洞合法。
- 等待第一个样本时，握手成功但 `start_window=0` 的数据被忽略；不开始邻域。
- 收集未满九个样本时接受新的 `start_window=1`，丢弃原部分邻域，当前像素成为新 p00。
- 收到第九个像素后开始计算，直到本次结果产生都不接收新样本；`in_ready=0` 时任何输入无效。
- 输出无反压，`out_valid` 为一个周期脉冲；`out_valid=0` 时 `uo_out=0`。
- 完成结果的边沿后回到等待状态，下一上升沿可接受新邻域。
- `busy` 在等待第一个样本时为 0，在部分收集和计算期间为 1。
- `rst_n=0` 或 `ena=0` 的上升沿清空部分样本和待输出事务，恢复输出零及空闲；这两者为低时 `in_ready=0`。
- reset 优先于输入和输出；恢复后必须从新 `start_window=1` 开始。

### 6.3 两种结构的周期约定

| 设计 | 第九个样本接受后，到输出的延迟 L | 连续发送时两个邻域首样本的间隔 II |
|---|---:|---:|
| `sobel_fast` | 2 个上升沿 | 11 个周期 |
| `sobel_compact` | 21 个上升沿 | 30 个周期 |
| `image_multi` 三种功能及 mode 3 | 2 个上升沿 | 11 个周期 |

定义例子：fast 的首样本在边沿 t 被接受，第九个在 t+8；输出在 t+10 后可见，下一事务首样本最早 t+11 接受。不得将其宣传为每周期处理一个输出像素。

fast 建议：输入寄存收集 → 第一个计算边沿登记梯度/加权和 → 第二个边沿完成绝对值/阈值/归一化/饱和并登记输出。

compact 建议：九像素收集完后，用共享加减资源顺序计算 Gx 的九项、Gy 的九项，共 18 个边沿；随后三个边沿完成 abs(Gx)、abs(Gy)、求和/阈值及输出。保留零系数步骤，便于先得到固定周期和可验证控制。

这是两份规格的设计约定，执行者要证明实际 RTL 满足。若两级结构无法满足时序，可另开明确标记的三级规格，重做 oracle、协议测试和指标；不能悄悄放宽原规格。每份结果保留自己的延迟和 II。

## 7. 验证设计：先有验收，再让 Agent 写 RTL

### 7.1 独立计算参考

由实施者依据上面的整数公式建立 Python 参考模型，固定灰度、边界、像素顺序和算子。参考模型不从候选 RTL 提取表达式，不依赖 OpenCV 默认 Sobel/blur 的边界或舍入行为。

先手算几组均匀邻域、极值阶跃、模糊和锐化结果；确认参考模型。随后冻结规格和测试文件，记录摘要。设计 Agent 只修改候选 RTL；冻结文件被修改的候选不能通过验收。

设计与验证任务可以使用 DSH 子任务，但不能把“另一个模型觉得对”作为 PASS。工具执行器运行真正的比较。

### 7.2 具体测试集合

| 测试层 | 内容 | 通过条件 |
|---|---|---|
| 算子定向 | 全 0、全 255、全 128、水平/垂直阶跃、极端邻域、阈值两侧、饱和边界 | 每个输出与独立整数模型一致 |
| 随机邻域 | 每种已声明算子至少 2,000 组；最终验收使用不同种子 | 零不匹配；像素覆盖 128–255 |
| 协议 | valid 空洞、握手受阻、部分事务重启、收集中/计算中 reset、ena、mode 变化 | 输出数目、顺序、值及边沿全部正确 |
| RTL 整图 | 每份设计至少三张固定 128×128 输入；含几何测试图与照片 | 输出逐像素精确一致，大小/边界正确 |
| 门级复验 | 每种功能至少 200 个定向/随机邻域、关键协议场景，以及一张固定 32×32 图 | 使用实际映射网表，零不匹配 |
| 性能计数 | 同一合规发送器连续发送至少 1,000 个邻域 | 实际测量 L、II、总时钟数，不靠规格常量填报告 |

测试须在边沿后稳定阶段采样，避免非阻塞赋值尚未更新造成假结果。测试计数为零、结果文件缺失、测试异常退出不能算 PASS。

Sobel 的 `M` 只能取偶数，阈值测试用 158、160、162：例如只有 p01 分别为 79、80、81，其余为零，输出应为 0、0、255。不要要求构造不可能的幅值 161。

对测试系统作一次故障验证：signed 像素错误、漏一个系数、valid 错位、reset 未清状态的版本应失败。错误版本明确放入测试校准目录，不混作自然设计失败或比赛成绩。

门级仿真先以映射网表的逻辑/周期复验为必需；STA 单独验证时序。若未做 SDF 仿真，报告不能暗示门级动态时序已经验证。形式证明可作为扩展，不是第一版的前置门槛；UNKNOWN 不算证明通过。
